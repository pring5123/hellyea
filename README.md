# 한미 폴더 백업 프로그램

![Build Status](https://github.com/pring5123/hellyea/workflows/Build%20Windows%20Backup%20Program/badge.svg)

C:\hanmi 폴더를 백업하는 간단한 GUI 백업 프로그램입니다.

## 다운로드

GitHub Actions에서 자동으로 빌드된 실행 파일을 다운로드할 수 있습니다:

1. [Actions 탭](../../actions) 방문
2. 최신 성공한 빌드 클릭
3. 하단의 "Artifacts" 섹션에서 `HanmiBackup-Windows-x64` 다운로드

또는 태그가 생성되면 [Releases 페이지](../../releases)에서 다운로드할 수 있습니다.

## 주요 기능

- **GUI 인터페이스**: 사용하기 쉬운 Windows GUI 프로그램
- **폴더 선택**: 백업할 폴더와 저장 위치를 자유롭게 선택 가능
- **자동 타임스탬프**: 백업할 때마다 타임스탬프가 포함된 폴더 생성
- **재귀 복사**: 하위 폴더와 파일을 모두 백업
- **진행 상황 표시**: 백업 진행 상황을 실시간으로 확인
- **자동 빌드 & 이메일 전송**: GitHub Actions로 자동 빌드 후 이메일 전송

## 시스템 요구사항

- Windows 7 이상
- C++ 컴파일러 (Visual Studio 또는 MinGW)
- CMake 3.15 이상

## 빌드 방법

### 방법 1: GitHub Actions 사용 (가장 쉬움)

코드를 푸시하면 GitHub Actions가 자동으로 Windows 환경에서 빌드합니다:

- Push나 PR 시 자동으로 빌드 실행
- 빌드된 `HanmiBackup.exe`는 Artifacts로 다운로드 가능
- v로 시작하는 태그 생성 시 자동으로 Release 생성

### 방법 2: 빌드 스크립트 사용 (로컬 빌드)

```batch
build.bat
```

### 방법 3: 수동 빌드

#### Visual Studio 사용

```batch
mkdir build
cd build
cmake .. -G "Visual Studio 17 2022"
cmake --build . --config Release
```

#### MinGW 사용

```batch
mkdir build
cd build
cmake .. -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build .
```

빌드가 완료되면 `build\bin\HanmiBackup.exe` 파일이 생성됩니다.

## 이메일 자동 전송 설정 (선택사항)

GitHub Actions 빌드가 성공하면 자동으로 `2024502@hanmisemi.com`으로 실행 파일을 이메일로 전송합니다.

**참고**: 이메일 설정은 선택사항입니다. Secrets를 설정하지 않아도 빌드는 정상적으로 완료되며, Artifacts에서 실행 파일을 다운로드할 수 있습니다.

### 1단계: Gmail 앱 비밀번호 생성

Gmail에서 이메일을 보내려면 **앱 비밀번호**가 필요합니다. (일반 Gmail 비밀번호가 아닙니다!)

#### Gmail 2단계 인증 활성화

1. **Google 계정 페이지 접속**
   - 브라우저에서 https://myaccount.google.com 접속
   - Gmail 계정으로 로그인

2. **보안 설정으로 이동**
   - 왼쪽 메뉴 또는 상단에서 **"보안"** 클릭
   - 아래로 스크롤하여 **"Google에 로그인"** 섹션 찾기

3. **2단계 인증 설정**
   - **"2단계 인증"** 항목 클릭
   - 이미 활성화되어 있다면 "사용 설정됨" 표시, 아니면 "사용 중지됨" 표시
   - **"사용 설정됨"이 아니라면:**
     - "시작하기" 버튼 클릭
     - 비밀번호 재입력
     - 전화번호 입력 (SMS 또는 음성 통화로 인증 코드 받기)
     - 인증 코드 입력하여 2단계 인증 완료

#### 앱 비밀번호 생성

2단계 인증이 활성화된 후:

1. **앱 비밀번호 메뉴 접근**
   - 같은 "보안" 페이지에서 **"Google에 로그인"** 섹션 확인
   - **"앱 비밀번호"** 항목 찾기 (2단계 인증 아래에 있음)
   - 클릭하면 비밀번호 재입력 요구됨

2. **앱 비밀번호 생성**
   - "앱 이름" 입력란에 **"GitHub Actions"** 입력 (또는 원하는 이름)
   - **"만들기"** 버튼 클릭
   - **16자리 비밀번호**가 생성됨 (예: `abcd efgh ijkl mnop`)
   - ⚠️ **중요**: 이 비밀번호는 한 번만 표시되므로 반드시 복사해두세요!

3. **비밀번호 저장**
   - 생성된 16자리 비밀번호를 복사 (공백 포함 또는 제외, 둘 다 가능)
   - 안전한 곳에 임시 저장

**참고**:
- 앱 비밀번호는 일반 Gmail 비밀번호와 다릅니다
- 앱 비밀번호 메뉴가 보이지 않으면 2단계 인증이 제대로 활성화되지 않은 것입니다
- 생성된 비밀번호는 나중에 다시 확인할 수 없으니 반드시 복사하세요

### 2단계: GitHub Secrets 설정

이제 GitHub 리포지토리에 이메일 정보를 안전하게 저장합니다.

1. **GitHub 리포지토리 페이지 접속**
   - 이 리포지토리 (pring5123/hellyea) 페이지로 이동
   - 상단 메뉴에서 **"Settings"** 탭 클릭
   - (Settings가 보이지 않으면 리포지토리 권한이 없는 것입니다)

2. **Secrets 설정 메뉴로 이동**
   - 왼쪽 사이드바에서 **"Secrets and variables"** 찾기
   - 하위 메뉴 **"Actions"** 클릭
   - "Repository secrets" 섹션이 표시됨

3. **첫 번째 Secret 추가: EMAIL_USERNAME**
   - 오른쪽 상단의 **"New repository secret"** 버튼 클릭
   - **Name**: `EMAIL_USERNAME` (정확히 입력!)
   - **Secret**: 발신자 Gmail 주소 입력 (예: `yourname@gmail.com`)
   - **"Add secret"** 버튼 클릭

4. **두 번째 Secret 추가: EMAIL_PASSWORD**
   - 다시 **"New repository secret"** 버튼 클릭
   - **Name**: `EMAIL_PASSWORD` (정확히 입력!)
   - **Secret**: 위에서 생성한 16자리 앱 비밀번호 입력 (공백 있어도 됨)
   - **"Add secret"** 버튼 클릭

5. **설정 완료 확인**
   - Secrets 목록에 `EMAIL_USERNAME`과 `EMAIL_PASSWORD`가 보이면 성공
   - Secret 값은 보안상 표시되지 않음 (●●●●●●로 표시)

### 3단계: 테스트

1. **코드 Push하여 빌드 트리거**
   - 아무 파일이나 수정하고 commit & push
   - 또는 GitHub Actions 탭에서 "Run workflow" 수동 실행

2. **빌드 완료 대기**
   - Actions 탭에서 빌드 진행 상황 확인
   - 약 5-10분 소요

3. **이메일 수신 확인**
   - `2024502@hanmisemi.com` 메일함 확인
   - 제목: "한미 백업 프로그램 빌드 완료"
   - 첨부파일: `HanmiBackup.exe`

### 문제 해결

**앱 비밀번호 메뉴가 보이지 않는 경우:**
- 2단계 인증이 제대로 활성화되었는지 확인
- Google Workspace 계정은 관리자 설정이 필요할 수 있음
- 다른 브라우저나 시크릿 모드에서 시도

**이메일이 전송되지 않는 경우:**
- GitHub Secrets에 `EMAIL_USERNAME`과 `EMAIL_PASSWORD`가 정확히 입력되었는지 확인
- Gmail 앱 비밀번호를 올바르게 복사했는지 확인
- Actions 탭에서 "Send email" 단계 로그 확인

**다른 이메일 서비스 사용:**
- Gmail 대신 다른 SMTP 서버를 사용하려면 `.github/workflows/build.yml` 파일의 `server_address`와 `server_port`를 수정하세요
- 예: Outlook (smtp.office365.com:587), Naver (smtp.naver.com:587)

## 사용 방법

1. `HanmiBackup.exe` 실행
2. 백업할 폴더 경로 확인/변경 (기본값: `C:\hanmi`)
3. 백업 저장 위치 확인/변경 (기본값: `C:\hanmi_backup`)
4. "백업 시작" 버튼 클릭
5. 백업 완료 대화상자 확인

## 라이선스

이 프로젝트는 자유롭게 사용, 수정, 배포할 수 있습니다.


- **메일 확인 (업무 공정 별 모니터링)**  
    디버깅같은 라인 업무 시작 전, 보통 타부서에서 메일을 보내는 것으로 인폼을 받고 시작함.  
    공정 별로 메일 종류는 이러함.  
    **1. 1차 디버깅 요청 메일 - 1차 디버깅 요청 / 비전 및 CCTV 검수 요청 / [와이어링부-업무참고]**  
    **2. 장비 이관 공유 메일 - [어셈-업무참고]**  
    **3. 2차 디버깅 요청 메일 - [테스트부-2차디버깅]**  
    **4. 장비 이슈 사항 공유 메일 - [테스트부-장비진행] / 장비진행 사항 공유**  
    **5. 품경 출하 검수 내용 공유 메일 - [품경-출하검수]**  
    상기 메일을 송부 받았다면, 각 메일 유형 별로 즉각 업무에 나서면 됨. 무슨 업무를 하는지는 하기 서술.  
    또한, 메일 뿐만 아니라 Ai연구본부 SA업무 공유방 카톡방에서도 메일이 날라오는대로 인폼을 해주고 있으니 카톡을 참조해도 상관 X  
    
- **1차 디버깅 시작 전 사전 작업 #**  
    1차 디버깅 전, 디버깅을 시작할 오더에 대한 아래 사항들을 체크해야 함.  
    **1. MMI 최신 프로그램, Secsgem DB, 서브앱 패치 BAT 파일이 다 구비가 되어 있는가?  
    **최신 프로그램 및 Secsgem DB가 서버 상에 존재하지 않다면 해당 오더의 담당 개발자에게 직접 연락 및 전달하여 서버에 업로드 할 수 있도록 추진.  
    Subapp 패치용 BAT 파일이 없는 경우엔 해당 오더에 제공하였던 hanmi 파일을 참조하여 그 파일 내에 들어있는 서브앱들을 통해 새로 Source 파일을 만들 것.  
    Y:\01. 혁신기술연구부\02. PC SETUP FOLDER\제어연구부 경로에 초기 한미 파일을 업로드 하니, 해당 경로를 참조.  
    만약 BAT파일이 있지만, 최신화가 안되어있는 경우엔 최신화를 시켜주어야 함. (Subapp 버전, ini 및 xml 파일 상 내용 수정이 추가로 필요한 경우)  
    **2. 생산의뢰서 내 2D Barcode 등 외부 업체 부속품이 포함되어 있는가?  
    **2DCode 등 추가로 세팅이 필요한 부속품이 있는 경우엔 1,2차 디버깅 시 세팅을 추가로 진행 해 주어야 함.  
    생산의뢰서 상에서도 발견되지 못한다면 세팅을 별도로 하지 않고 출하까지 진행.   
    **3. 해당 오더의 체크리스트 파일이 서버 상에 업로드가 되어있는가?  
    **없는 경우, X:\부서별\MMI연구부\#디버깅체크리스트파일\__기본양식 해당 경로에서 해당 오더의 장비군에 따라서 체크리스트를 새로 만들 것.  
    각 체크리스트 별로 체크 할 내용이 조금씩 다르니 혼동하지 않게 주의할 것.  
    이 3가지가 전부 확인되었다면 와이어링부 측에서 송부하는 메일 혹은 Ai연구본부 SA업무 공유방 카톡방에서 인폼 주는대로 1차디버깅 진행.  
    
- **1차 디버깅 #MMI Vision**  
    와이어링부 측에서 메일을 송부했을 때, 메일 내용에 있는 장비 오더 번호 및 위치를 보고 1차디버깅 진행.  
    서버에 업로드 되어있는 체크리스트를 통해 디버깅을 진행하므로, 진행 전 먼저 해당 장비 PC가 서버에 연결되어있는지 부터 체크 필요.  
    이후, 라우터 세팅부터 진행하여 Vision PC, SEQ PC 전체 한미 서버에 접속될 수 있도록 초기 네트워크 세팅 진행.  
    모든 사전 준비가 마쳐졌다면 서버에 있는 체크리스트를 통해 1차 디버깅 진행 (노란색 마킹이 되어있는 항목이 1차 디버깅 체크 사항)  
    MMI 프로그램 패치 / SubApp 패치 / 기본 PC 세팅 (Bios, Router, NTP, etc.) 은 전부 1차에서 확인.  
    
- **2차 디버깅**  
    1차 디버깅이 종료된 후, 테스트부 측으로 장비가 이관이 될 때, 어셈블리부측에서 메일을 송부함.  
    이 메일을 수신받고 약 하루정도 뒤에 테스트부 측으로 완전히 이관이 되고, PC 전원도 인가됨.  
    모든 준비가 마쳐지면, 1차디버깅 때 사용하였던 체크리스트를 통해 2차디버깅 진행.  
    체크 항목들을 전부 체크 한 뒤, MMI 프로그램 내 전체 화면을 캡쳐하는 작업이 필요함.  
    가능한 모든 화면을 전부 다 캡쳐하는 것이 목적이며, 기존 영어 외에도 다국어 또한 확인해야 함.

    **2. n주차**

    어떠한 오더에 대한 모든 정보를 다 담는 테이블이라고 보면 되며, 특히나 해당 장비의 위치까지 모니터링 해야 하기에  
    매주 월 / 수 / 금 마다 꾸준히 점검하여 갱신 할 수 있도록 해야 함.

- **월평가 #**  
    매월 1일이 되는 시점, 혹은 1주일 전 MMI.공유 메일로 월평가 공지를 MMI연구부 전체에 송부.

    내 PC\ECM 드라이브 (U:)\공통폴더\한미반도체\부서폴더\융합기술연구본부\MMI연구부\07. 일반 문서\01.관리문서\10.월별 업무 평가\2026년 귀속 (2025.11 ~ )\월평가 SA 원본  
    위 경로에 마지막으로 작업한 문서가 업로드 되어 있으며, 해당 문서를 통해 작업을 진행하면 됨.  
    또한, 월평가 집계 시 주의해야 할 사항들로 하기 정리함.
    
    **1. 모든 데이터는 HPMS / 출장자양식 엑셀파일 과 동일해야 함.  
    **보통 HMPS에 작성되는 내용 중 위 표와 내용의 개수가 맞지 않는 경우가 빈번함.  
    이런 경우에는 바로 수정할 수 있게 작성자에게 직접 연락하는 쪽으로 진행해야 함.  
    출장자의 경우에는 유선 연락 후 상의 하에 진행 (어짜피 작성하는 건 작성자 재량으로 하는 것이기에 대부분 그냥 지워달라 할거임)  
    본인이 집계하다가 누락이 되는 경우도 있지만 이렇게 애초부터 잘못 작성되서 누락이 된 것 처럼 보이는 경우도 있으니 확실히 잡아낼것
    
    **2. 중복된 내용이 있을 경우, 붉은색으로 폰트에 음영처리 시킬 것**  
    위 사진과 같이 집계된 내용 중 똑같은 내용으로, 설명도 없이 같은 내용을 여러번 올렸을 시, 이 내용은 집계 대상에서 제외됨.  
    아에 집계를 하지 말라는 게 아니라, 작성자가 잘못 인지하고 있는 내용을 구분할 수 있게 음영처리를 해달라는 것.  
    엑셀 매크로에도 해당 내용은 집계가 되지 않게끔 제외탭에 1까지 작성 해 줄 것.
    
    **3. 추가적으로 작성자가 설명을 붙였을 경우엔 그 설명까지 내용에 포함시킬 것**  
    HPE-0000 수정 (100% ~) 이런식으로 여러개 작성했다고 쳤을 때, 해당 건과 같은 오더, 다른 내용으로 작성하면  
    내용들이 구분이 되면 모르겠지만, 막 적어냈을 경우 저 내용들이 다른 내용인지 구분이 가지를 않음  
    2번에서 설명 했듯이, 같은 내용이면 집계 대상에서 제외가 되기 때문에 이런 실수들을 막기 위해서 구분하도록 메일까지 써서 전파한 것.  
    옆 혹은 아래에 부가 설명이 있다면 이런식으로 집계 후 내용들을 체크 할 때 구분이 갈 수 있으니까  
    되도록이면 작성자가 설명까지 붙여서 썼다면 그 내용도 테이블에 집어넣도록 할 것.
    
    **4. 월평가 자료를 전달받지 못했을 경우 팀장에게 보고할 것**  
    메일 내 내용으로는 유예기간으로 3일이라는 시간을 주지만, 이 날짜 안에 받지 못했을 경우, 그 즉시 작성자 소속 팀 팀장에게 전파  
    그 인원이 출장을 갔든, 휴가를 갔든, 사내에 없든 뭐든 간에 팀장에 전파하는 건 당연한 수순. (부서장 주관 팀장미팅 때 얘기를 수도 없이 했으니 알아서 할 것임)  
    그 뒤로는 솔직히 작성자 재량으로 보내느냐 마냐의 문제이기 때문에 이 이상 SA 인원이 관여하는 건 불필요함  
    만약 팀장급에서도 해결이 되지 않으면 해당 인원만 집계 제외 후 원래 하던대로 부서장님께 보고할 것.
